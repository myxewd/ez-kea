{# One option row, shared by the three option tables (global settings, client classes, per-reservation). A row is one of two things, and the ✕ means something different for each: * class option-row-saved -- the option already exists in the Kea config. The ✕ strikes the row through and records it for removal; saving the form deletes it. Clicking the same ✕ again puts the row back, so a mistaken removal is undoable right up until the save. * no such class -- a row the user just added in this edit. Nothing exists server-side yet, so the ✕ simply drops the row. The class is what the JavaScript dispatches on (see the script at the bottom of this file). The hidden field is never visible: the ✕ drives it. A removed row's fields are readonly rather than disabled, so their values stay in the submission and a save that fails validation can re-render the row. #} {% import "_icons.html" as icons %} {% macro option_row(prefix, index, name, data, saved, deleted=False, name_placeholder='e.g. root-path', data_placeholder='value') %} {% endmacro %}
