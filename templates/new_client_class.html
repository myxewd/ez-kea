Kea identifies a class by its name, so renaming one is a rename of the class itself.

Written into the config verbatim and parsed by Kea — a typo is reported by Test Config / Apply Changes, not here. A few checks that were verified against real client packets: substring(option[77].hex, 0, 4) == 'iPXE' (the iPXE user class — matches the booted iPXE, not the firmware that loaded it), option[93].hex == 0x0007 (client architecture: 7 is x86-64 UEFI, 0 is BIOS), substring(option[60].hex, 0, 9) == 'PXEClient' (any PXE client).
Two things worth knowing: option[N].hex is the option payload as bytes, so substring offsets and lengths count bytes and a quoted string is compared byte for byte. And a loaded iPXE announces itself in option 77, not option 60 — both the firmware and iPXE send a PXEClient:Arch:...:UNDI:... vendor class, so option 60 cannot tell the two stages apart.
