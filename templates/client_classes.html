A client class is a named condition over the incoming packet. Kea evaluates each class's expression against every request; clients that match get whatever the class carries — options, lease lifetimes, and (DHCPv4) the fixed BOOTP header fields next-server / boot-file-name.

Expressions are written through exactly as typed and judged by Kea's own parser at Test Config — EZ-KEA does not attempt to interpret them, and it cannot tell you which class a real client will match. Kea's expression vocabulary is documented in the Kea ARM, Client Classification.

Classes are tried in the order they appear below, and Kea uses the first matching class's boot fields and options — so a class higher in the table outranks a later one. EZ-KEA keeps the per-host iPXE classes it generates (marked Managed) at the top, which is what lets one host's script outrank a general iPXE class; they are changed on the reservation that owns them, not here.
